# BarberPro — мультитенантная платформа (FastAPI + SQL + React, PWA, JWT)

Платформа для сети барбершопов с **тремя уровнями доступа**:

1. **Владелец платформы (суперадмин)** — добавляет барбершопы ("точки"),
   выдаёт каждому логин и пароль администратора. Не видит и не может
   увидеть ни одной записи, клиента, барбера, выплаты или отчёта ни одной
   точки — технически это невозможно, потому что у каждого барбершопа
   **собственная, физически отдельная база данных**.
2. **Администратор барбершопа** — получает от суперадмина логин и пароль,
   заходит на свою личную панель и управляет всем: барберы, услуги,
   записи клиентов (недельный календарь), отчёты, выплаты, настройки.
   Видит только свою точку.
3. **Барбер** — добавляется администратором своего барбершопа, заходит
   под собственным логином/паролем, принимает заявки и может сам
   записывать клиентов напрямую, без участия админа.

Бэкенд — FastAPI + SQLAlchemy, фронтенд — React (Vite), в виде **PWA**
(устанавливается как приложение), авторизация — **JWT**.

## Как устроена изоляция данных

```
                    ┌─────────────────────────┐
                    │   MASTER DATABASE         │   ← видит только суперадмин
                    │   (master.db)               │
                    │  - суперадмин (1 аккаунт)     │
                    │  - список барбершопов           │
                    │    (название, логин админа,      │
                    │     хеш пароля, активен ли)       │
                    │  - служебный индекс login→точка    │
                    │    (для входа барберов, БЕЗ паролей)│
                    └─────────────────────────────────────┘

  tenants_data/salon-almaty.db      tenants_data/salon-astana.db     ...
  ┌───────────────────────┐        ┌───────────────────────┐
  │ ПОЛНОСТЬЮ ОТДЕЛЬНАЯ БД │        │ ПОЛНОСТЬЮ ОТДЕЛЬНАЯ БД │
  │  - барберы              │        │  - барберы              │
  │  - клиенты                │        │  - клиенты                │
  │  - услуги                   │        │  - услуги                   │
  │  - записи (bookings)          │        │  - записи (bookings)          │
  │  - выплаты                       │        │  - выплаты                       │
  │  - настройки                        │        │  - настройки                        │
  └─────────────────────────────────────┘        └─────────────────────────────────────┘
```

Когда суперадмин создаёт барбершоп (`POST /superadmin/tenants`), backend:
1. Генерирует уникальный slug (например «Salon Almaty» → `salon-almaty`).
2. Сохраняет в master-базе только: название, slug, логин и **хеш** пароля
   администратора, флаг активности.
3. Создаёт для этой точки **новый файл базы данных**
   `tenants_data/salon-almaty.db` со всей нужной схемой (барберы, клиенты,
   услуги, записи, выплаты, настройки) — пустой, готовый к работе.

С этого момента вся бизнес-логика точки живёт только в её собственном
файле БД. Ни один API-эндпоинт суперадмина не открывает файлы точек —
физически нет кода, который мог бы это сделать.

Когда барбер логинится, backend сначала смотрит в служебный индекс
master-базы («этот логин принадлежит точке salon-almaty»), затем **пароль
проверяется уже внутри базы данных именно этой точки** — сам пароль
барбера никогда не покидает его файл БД.

## Структура проекта

```
barberpro/
├── backend/
│   ├── app/
│   │   ├── main.py                  # точка входа, master-БД, сид суперадмина
│   │   ├── config.py                 # настройки из .env (master БД, папка точек, JWT)
│   │   ├── master_database.py         # подключение к платформенной БД
│   │   ├── master_models.py            # PlatformAdmin, Tenant, LoginIndex
│   │   ├── tenant_db.py                 # создание/кэш БД на каждую точку, slug, удаление
│   │   ├── database.py                   # Base для схемы точки (users/clients/.../settings)
│   │   ├── models.py                      # таблицы ВНУТРИ одной точки
│   │   ├── schemas.py                      # Pydantic-схемы
│   │   ├── security.py                      # хэширование паролей + JWT
│   │   ├── deps.py                           # require_superadmin / require_tenant_admin / require_tenant_barber
│   │   ├── utils.py                           # общие функции отчётов
│   │   └── routers/
│   │       ├── auth.py                          # единый /auth/login на все 3 роли
│   │       ├── superadmin.py                     # CRUD барбершопов (только суперадмин)
│   │       ├── admin.py                           # барберы, записи, отчёт, выплаты, настройки — точки
│   │       ├── barber.py                           # заявки, свой календарь, свой отчёт — барбера
│   │       ├── services.py                          # каталог услуг точки
│   │       ├── clients.py                            # клиенты точки
│   │       └── settings.py                            # рабочие часы/шаг слота точки
│   ├── requirements.txt
│   └── .env.example
│
└── frontend/                   # React + Vite + PWA
    ├── src/
    │   ├── context/AuthContext.jsx   # роль: superadmin | admin | barber
    │   ├── App.jsx                    # /superadmin/*, /admin/*, /barber/*
    │   └── pages/
    │       ├── Login.jsx                # одна форма на все роли
    │       ├── superadmin/                # Tenants.jsx — добавление/управление точками
    │       ├── admin/                      # Bookings, Barbers, Reports, Payments, Services, Settings
    │       └── barber/                      # Calendar, Requests, Reports, Services
    └── ...
```

## Запуск backend

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt

cp .env.example .env            # отредактируйте SUPERADMIN_LOGIN/PASSWORD
uvicorn app.main:app --reload   # http://localhost:8000
```

При первом запуске:
- создаётся master-база (`master.db`) со списком точек (пока пустым);
- создаётся единственный аккаунт **суперадмина**: логин/пароль из `.env`
  (по умолчанию `superadmin` / `super123` — **обязательно смените** перед
  реальным использованием);
- папка `tenants_data/` создаётся автоматически при добавлении первой точки.

Документация API: `http://localhost:8000/docs`.

## Запуск frontend

```bash
cd frontend
npm install
cp .env.example .env
npm run dev                     # http://localhost:5173
```

## Как этим пользоваться

1. **Вы (владелец платформы)** заходите под `superadmin` / `super123`
   (или тем, что указали в `.env`). Попадаете на экран «Барбершопы».
   Нажимаете «+ Добавить барбершоп», вводите название, придумываете
   (или генерируете кнопкой) логин и пароль администратора.
2. **Передаёте эти логин и пароль клиенту** (владельцу барбершопа) —
   любым удобным способом, вручную. Платформа сама ничего не отправляет.
3. **Клиент заходит** на тот же сайт под своим логином/паролем и
   автоматически попадает в свою собственную панель администратора —
   ровно тот же интерфейс, что был в предыдущей версии BarberPro
   (календарь записей на неделю, барберы, отчёты, выплаты, услуги,
   настройки), но полностью изолированную от других точек.
4. **Клиент сам добавляет своих барберов** (кнопка «+ Добавить барбера»
   на странице «Барберы») — без каких-либо ограничений по количеству и
   без участия суперадмина. Каждый барбер получает свой логин/пароль от
   администратора точки и заходит в свой личный кабинет.
5. **Барбер** видит недельный календарь, может сам записывать клиентов
   напрямую (без участия админа) и отмечать визиты как «Выполнено».

Ни один шаг не требует правки кода — всё через интерфейс.

## Безопасность и продакшен

- Смените `SUPERADMIN_LOGIN`/`SUPERADMIN_PASSWORD` в `.env` сразу после
  первого запуска.
- Смените `SECRET_KEY` на длинную случайную строку.
- Пароли (суперадмина, админов точек, барберов) хранятся как bcrypt-хэши;
  все SQL-запросы идут через ORM (SQLAlchemy) — исключены SQL-инъекции.
- Master-база (`master.db`) — единственное место, где в принципе можно
  узнать список точек и их логины администраторов; ограничьте доступ к
  файлам сервера соответствующим образом. Файлы точек в `tenants_data/`
  не читает ничего, кроме кода, который обслуживает конкретный, уже
  аутентифицированный запрос именно этой точки.
- В `CORS_ORIGINS` для продакшена укажите точный список доменов.
- Для очень большого числа точек можно переключить хранение точек с
  файлов SQLite на MySQL/PostgreSQL — см. `TENANT_DATABASE_URL_TEMPLATE`
  в `.env.example` (по одной базе/схеме на точку, код менять не нужно).
